# HV Monster Manager（怪物管理器）

作者：KirisameReiko  
当前版本：0.3.5.0

## 用途与适用页面

这是一个依赖 **HV Utils 4.2.4** 的 HentaiVerse Monster Lab 附属脚本，支持选择怪物、怪物重命名、24 项升级草案、精确 PL 与混沌升级、水晶库存检查及采购。它直接使用 HV Utils 已生成的 Monster Lab 列表、侧栏、主题变量和 `hvut_prices` 共享价格，不提供独立侧栏或独立页面布局。脚本仅运行于以下两个基础地址：

- `https://hentaiverse.org/?s=Bazaar&ss=ml`
- `https://alt.hentaiverse.org/?s=Bazaar&ss=ml`

匹配采用参数集合白名单判断；允许参数顺序变化和可选的 `#planner/<正整数编号>` 深链接，两个域名上的 `ss=ar`、重复参数、其他附加参数及其他片段均不会启动脚本。

## 安装与权限

先安装并启用 `HV Utils-4.2.4.js`，再将 `HV Monster Manager.js` 导入 Tampermonkey，并在 HV Utils 设置中开启 **Advanced MonsterLab features**。附属脚本会等待 `.hvut-ml-side`、`#hvut-ml-up-button` 和 `#mainpane`；15 秒内仍找不到宿主时会显示双语依赖错误，不会创建独立回退界面。

脚本使用以下权限：

- `GM_addStyle`：添加怪物管理器界面样式。
- `GM_getValue` / `GM_setValue`：保存语言、目标 PL、价格来源／自定义收购价、已选怪物编号和重命名设置，以及共享的怪物等级与市场快照缓存。

除 HV Utils 4.2.4 外不需要其他依赖，也不向 Hentaiverse 以外的站点发送数据。Tampermonkey 会把不同用户脚本放在彼此隔离的沙箱中，因此 HV Utils 的 `$ajax`、`$item`、`$price`、`$config` 和 `_ml` 私有变量无法由附属脚本直接调用；当前版本只依赖其可观察的 DOM 与页面共享缓存，实时 POST 校验、精确求解和重命名仍保留为本脚本的安全核心。

“PL计划器”和“怪物重命名”面板顶部都提供 English／简体中文切换按钮，两处共用并持久保存同一语言设置。在任一面板切换语言后，两个侧边入口和另一个面板都会同步更新；首次运行不再弹出 `0/1` 语言对话框。

## 使用方法

1. 打开 Monster Lab；HV Utils 初始化完成后，“PL计划器”和“怪物重命名”会追加到其 `.hvut-ml-side` 侧栏中。
2. 展开“选择怪物”，普通单击只选择当前项，Ctrl+单击添加或取消单项，Shift+单击按栏目当前显示顺序连续选择，Ctrl+Shift+单击把连续范围加入已有选择；列表获得焦点后可按 Ctrl+A 全选，单击列表空白处可清空。PL 计划器和怪物重命名共用同一份选择，页面刷新后仍保留已选编号。
3. 在“PL计划器”设置目标 PL 和价格来源。选中怪物后，脚本最多并发读取 5 只怪物的 12 项水晶属性、12 项混沌升级、水晶库存和混沌令牌；每行独立显示载入或错误状态。取消选择不会丢失本页草案，刷新页面后草案清除。
4. 升级编辑器始终展开：桌面显示 24 项矩阵，900px 以下显示可同时展开多张的怪物卡。每格保留当前等级和目标等级；空值、非整数、低于当前值或超过项目上限都会原样标错并阻止计算、确认和执行，不会自动修正。
5. “计算精确方案”只求解 6 项主要属性和 6 项元素减伤，12 项混沌升级保持当前值。手动改水晶属性时，该怪物投影 PL 必须精确等于目标；只改混沌时可忽略 PL 差异；同批可混合精确 PL 与仅混沌怪物，完全未修改的行会自动忽略。
6. 资源区汇总 12 种水晶和混沌令牌，默认隐藏需求为 0 的项目，可展开全部 13 项。水晶可继续直接买入或挂买单；混沌令牌不可购买。执行前使用默认聚焦“取消”的双语对话框显示批次及资源摘要，并可展开逐怪明细。

怪物等级和市场刷新结果以结构化 GM 对象保存在 `hv_monster_manager_cache_v1`，主域名和备用域名共用同一缓存。怪物记录包含名字、PL、更新时间、12 项水晶等级和可选的 12 项混沌等级；旧缓存仍可读取。只有当前列表 PL、缓存 PL 和水晶等级计算 PL 三者一致时才会恢复，当前列表名字始终覆盖缓存旧名字。混沌令牌库存和升级草案不持久化。市场记录继续包含库存、批量、价格、订单和订单簿；`CACHE_VERSION` 仍为 1。

缓存不会取代操作前的实时安全检查：升级前仍重新读取全部选中怪物并规划，购买前仍刷新市场，重命名前仍读取最新名单；成功刷新、升级响应、市场响应和重命名响应会立即同步缓存。PL 发生变化、缓存版本不兼容、字段损坏或怪物已不存在时，对应记录会自动失效或清理。

“PL计划器”由左侧怪物选择和右侧“计划设置 → 升级编辑器 → 资源 → 日志”组成；资源和日志均可折叠，缺口或错误会自动展开对应区域。订单簿不能完整覆盖所需批数时，只显示可见／所需批数，不把局部花费冒充总价。“怪物重命名”面板继续按“选择怪物 → 重命名”排列，选择状态与计划器共享。

未安装 dokidoki 时，面板仍是 `#mainpane` 内的 `.hvut-ml-up` 子视图，默认宽度为 HV Utils 主面板的 100%。如需缩窄，可在用户样式或脚本 CSS 中设置：

```css
:root { --hvmm-panel-width: 900px; }
```

安装 dokidoki 0.2.1.0 后，两个入口会随真实 `.hvut-ml-side` 进入顶部工具栏；面板挂载到 `#dokidoki-addon-host` 并替换怪物列表工作区，颜色映射为纸面、深棕、琥珀和黄铜。关闭管理器或打开其他 HV Utils 工具会恢复列表。两种加载顺序都会迁移同一节点，不重建语言、选择或草案；dokidoki 不可用时保留原布局和主题回退。

升级执行冻结当前显示顺序并逐怪处理，每只先水晶、后混沌；所有 POST 严格串行且每次最多 10 级。开始时强制重读全部有效怪物并校验整个剩余批次；精确模式每次响应后重新调用 `solveExact()`，自定义模式比较固定 24 项目标，不保留旧请求队列。解析失败、等级下降、越界、PL 超标、无进展、库存未知、资源不足、state-lock 或不可精确到达时立即停止整个批次。POST 超时、断网或结果不明时不会自动重试，只诊断 GET 一次并回写可确认状态，必须重新确认后才能继续。

附属脚本请求起始时间继续遵守 300ms 间隔；混沌状态懒加载最多 5 个并发，POST 始终串行。实际升级、改名或水晶成交会使 HV Utils 当前页内的私有缓存过期，因此脚本会禁用该页的 Monster Upgrader 并显示“重新加载页面”；重新加载后 HV Utils 会重新同步最新状态。

## 怪物重命名

点击侧边的“怪物重命名”进入独立面板，支持先点击“导出全部怪物名字”生成 `hv-monster-names.txt`。导出文件每行格式为 `编号,当前名字,`，在第三列填写新名字后即可直接导入或粘贴。文件选择区使用脚本自己的双语按钮和文件名状态，不再显示由浏览器界面语言决定的原生“选择文件／未选择任何文件”文字：

- TXT／粘贴映射：每个非空行写成 `编号,当前名字,新名字`。脚本只处理同时存在于映射和当前选择中的怪物，并核对当前名字是否仍与实时列表一致；编号无效或重复、当前名字过期、当前名字或目标名字重复、列数错误时会明确阻止或跳过对应映射。
- 随机数字：选择需要重命名的怪物，输入名字前缀，脚本为每只怪物生成“前缀 + 6 位随机数字”。本地重复或服务器提示名字已占用时会换一个后缀，单只怪物最多尝试 8 次。

执行前脚本会重新读取 Monster Lab 列表并显示确认框。每次 POST 都解析服务器返回页中的实际名字：TXT 的精确目标被占用时只记录失败并继续，不会擅自换名；返回无效或名字变成非预期值时立即停止，避免在并发修改下继续操作。

## 已知限制

- HV Utils 4.2.4 没有公开跨用户脚本 API；其私有沙箱变量无法直接复用。附属脚本通过稳定 DOM 和 `localStorage` 共享价格工作，HV Utils 若改变 Monster Upgrader 表格结构，脚本会拒绝把无法确认的数据当作实时状态，并回退或停止。
- Hentaiverse 只提供“增加等级”请求，没有原子化的“升级到目标 PL”接口。实时响应重算能消除脚本自身固定队列造成的过升，但无法彻底消除其他标签页或脚本在两个请求之间同时修改同一怪物的竞争条件。
- 为减少请求量，脚本不会在每个 POST 前额外读取怪物；执行开始时读取全部怪物，之后以每个 POST 的响应页作为最新状态。
- 已高于目标 PL 的怪物无法降级，包含此类怪物的批量计划不可执行。
- 实际升级会消耗水晶且不可撤销；请在确认框中核对最新计划。
- 怪物名字是否可用只能由 Hentaiverse 在提交时确认；预览无法预先保证目标名字未被其他玩家占用。
- 市场当前卖单不足时无法可靠推算后续卖单价格，因此脚本不会把已显示部分的花费冒充完整预估；直接买入会在每轮后刷新订单簿再决定下一笔请求。
- 当前页发生实际怪物或水晶变更后，需按面板提示重新加载页面，才能继续使用 HV Utils 自带的 Monster Upgrader；这是为了避免其页面内私有缓存继续显示旧等级或旧库存。
- 持久缓存按当前用户脚本安装共享，不区分同一浏览器配置中的多个 Hentaiverse 账号；缓存只用于预览，任何升级、购买或重命名提交前都会重新读取服务器状态。
- `0.3.1.x` 分支曾按要求从 `0.4.0.0` 调整为 `0.3.1.0`，部分用户脚本管理器不会自动用较低版本覆盖较高版本，需要手动重新安装脚本。

### 0.4.0.0

架构改为 HV Utils 4.2.4 附属脚本：严格等待其 Monster Lab 侧栏、主面板和 Upgrader；怪物列表、常规等级／库存快照、主题与 `hvut_prices` 缓存优先复用 HV Utils 的 DOM 实现。删除独立侧栏、3 秒独立回退、fixed overlay、独立硬编码主题、无效的跨脚本 GM 价格同步和确认阶段固定请求数组；面板直接挂载为 `#mainpane` 下的 `.hvut-ml-up` 子视图，请求策略统一为 300ms 间隔／最多 4 个并发读取。

HV Utils Upgrader 中带保存目标的行不会被误当作实时等级，而会改为直接读取对应怪物详情；实际升级、重命名或水晶成交后会标记 HV Utils 当前页缓存过期、禁用其 Upgrader 并提供重新加载按钮。版本同步加入专用架构测试和 Chrome 宿主夹具；真实 Chrome 验证同时修复了从中文切回英文后“已选怪物／已缓存”动态摘要未翻译的问题，英文版的 `Choose File` 与 `No file selected` 也再次确认无中文残留。

### 0.3.0.0

不完整订单簿不再显示类似“7.319 MC for 51,353/55,867 visible batch(es)”的局部金额，改为明确提示无法估算完整消耗并保留覆盖批数；水晶需求栏目默认折叠，水晶收购价新增“自定义”并在选择后自动展开栏目且保留手动价格，“市场价来源”和“收购价来源”分别更名为“水晶市场价”和“水晶收购价”；刷新、直接买入、挂买单和升级四个按钮统一放在顶层同一行，重命名面板改为“选择怪物 → 重命名”，同步补全中英文文案，并删除旧版独立语言存储及其迁移代码。

### 0.2.13.0

### 0.2.12.0

将怪物管理器拆分为“PL计划器”和“怪物重命名”两个独立入口与面板，新增全部怪物名字的一键导出并把导入导出统一为带编号的三列模板，重命名面板移除日志栏目，水晶需求默认展开并将等级、库存、订单和价格读取合并为“刷新数据”，直接买入水晶、挂水晶买单和收购价来源移到 PL 面板顶部，同时精简升级与购买按钮文案，语言改为首次运行时通过 `0/1` 对话框全局选择，面板宽度缩窄为最多 900px。

### 0.2.11.0

脚本和面板更名为“怪物管理器”，“批量重命名”改为“怪物重命名”，“批量选择怪物”改为“选择怪物”，面板按怪物重命名、选择怪物、水晶需求与库存缺口、升级方案、日志的顺序重组，重命名、选择和水晶栏默认收起而日志默认展开，升级内容统一收入“升级方案”，原先分散的 PL 摘要和操作状态合并为单一日志输出区。

### 0.2.10.0

新增批量重命名：支持读取或粘贴 `当前名字,新名字` TXT 映射，也支持为勾选怪物生成“前缀 + 6 位随机数字”的名字；执行前重新读取列表，每次响应校验实际名字，随机名字占用时自动换号重试，精确映射占用时保持原名并明确报告。修复详情页参数读取，使严格 URL 守卫与页面内部查询参数能够同时工作。

### 0.2.9

将备用域名 `https://alt.hentaiverse.org/?s=Bazaar&ss=ml` 加入精确 URL 白名单；主域名和备用域名仍只匹配 Monster Lab 的完整标准地址。

### 0.2.8

将用户脚本元数据和运行时守卫同时收紧为 Monster Lab 主域名完整 URL 全等匹配，避免 `ss=ar`、备用域名或带附加参数的页面被脚本管理器判定或实际执行。

### 0.2.7

升级执行改为实时目标模式，执行开始时按最新怪物状态重建方案，每次升级响应后同步实际等级与水晶库存并重新规划剩余批次，达到目标后不再执行旧增量，遇到越界、不可达、无进展或库存不足立即停止，最终成功条件改为所有怪物实际 PL 精确等于目标。
