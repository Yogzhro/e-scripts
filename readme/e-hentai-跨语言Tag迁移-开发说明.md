# E-Hentai 跨语言画廊 Tag 迁移

- 主脚本：`eh-tag-transfer.js`
- 作者：`reina`
- 当前版本：`0.2.5.0`

## 用途

脚本既可在 E-Hentai 或 ExHentai 画廊详情页处理当前作品，也可停留在两站主页增量发现新画廊。主页只负责发现和排队；标题、页数、语言、标签状态与写入仍在后台读取完整详情页后验证，用户不需要逐个打开画廊。

当前版本的主要行为：

- 主页队列：首次运行只记录当前列表为基线，以后按 GID 去重并持久化排队；每轮在请求预算内连续处理全部就绪任务，不再固定只取一个画廊，也不会以 `500` 条静默截断队列。
- 四阶段搜索：搜索编排明确分为“发现、预筛、渐进详情、最终选择”；发现阶段仍先用 `#gn` 英文／罗马字标题，只有没有合规候选时才用 `#gj` 日文标题回退。
- 章节身份：识别 `Ch.`、`Chapter`、`Vol.`、`Episode`、`Part`、`第…話/巻`、韩文章节和特殊章节等后缀，搜索词保留章节，候选双方章节明确冲突时拒绝。
- 候选验证：只使用绝对页差，不再检查相对页差；Digital 与展会信息会从核心标题中清理，但不再参与候选验证和评分。标题两侧署名明确冲突、作品编号冲突、短标题没有共同创作者证据，或非完全相同标题缺少章节、原作段、标题署名及实线作者／社团中的任一独立依据时直接拒绝。
- 请求控制：Fetch、直连 XHR 与 `GM_xmlhttpRequest` 共用一套超时、取消、底层中止、监听清理和单次结算内核；搜索间隔默认与下限均为 `3000` 毫秒，主页总请求上限默认 `120`。
- 完全直连：读取画廊 HTML 中站点提供的 `api_url/apiuid/apikey/gid/token`，通过官方 `taggallery` JSON 协议写入；脚本不再创建隐藏 iframe，也不再点击标签菜单或调用页面 `send_vote`。
- 修正状态保护：`other:uncensored` 不再随普通标签并集跨分支传播；目标 GN/GJ 只有在独立括号元数据中明确出现无修正或去修正标记时才直接生成该标签，未标注、有修正、互相冲突或否定表达都会安全拦截，普通标签继续迁移。
- 人工踩票保护：目标标签带 `tdn` 时从待赞和提交前计划中排除，脚本不会再用自动迁移覆盖用户已有踩票；状态和关键日志会列出跳过数量及标签。
- 随机少迁移：默认从整个迁移任务真正待提交的唯一标签中随机省略 `0–3` 个，并保证至少留下一个；所有目标共享同一省略集合，省略只影响本次普通迁移，不改变错误标签纠正。
- 真实写入：`0.1.8.2` 已完整移除临时只读演练层，迁移、错误标签纠正、主页队列和终态指纹均恢复正式行为；写入仍由中央直连客户端统一执行并在每次 POST 后重新读取验证。
- 源码可读性：`0.1.8.3` 将压缩主体恢复为带换行和四空格缩进的可读排版；参数名、默认值、中文注释、分支、接口和写入行为均未修改。
- 统一测试：`0.2.3.0` 将匹配黄金样本、请求生命周期、版本与调度、主页十周期刷新、Repository 审计、TXT、正式模式和语义命名检查全部合并进一个无第三方依赖的入口；同一入口也可启动 Chrome 人工夹具。
- 语义命名：`0.1.8.5` 将 Terser 混淆留下的顶层、函数参数、局部变量、回调、循环和异常分支短名称恢复为按当前逻辑重建的语义名称，并加入全文件残余审计；由于 `0.1.8.0` 未保留 source map，这些名称不能证明与压缩前源码逐字相同，但运行语义没有变化。
- 模块分层：单文件主体按配置、持久状态、纯规则、统一请求、直连写入、搜索迁移、调度/UI 和测试入口八层组织；`0.2.3.0` 删除无隔离价值的请求与调度门面，并把 Node `CORE` 收束为按职责分组的高层安全测试接口。
- 可读性优先：`0.2.3.0` 不使用 Terser、变量缩写或混淆，删除压缩布尔值、匿名执行块和大量副作用逗号表达式，保留完整语义名称、顶部逐行参数区和 CRLF。
- 极简面板：面板固定在右下角，四个按钮按两行两列排列，仅保留固定三行高的截断状态栏和最近 `20` 条关键日志；拖动、最小化、布局定位和 UI 状态存储均已移除。
- 版本重建：脚本版本变化时，两站各自清除主页队列、扫描基线、调度窗口、下一运行时间、租约、运行标记和旧 UI 状态；共享版本标记同时解除全局停止，再按当前每日时间窗自动恢复。`badTags.v3` 的 UID 和历史指纹保留。
- 定时波动：`0.2.1.0` 引入每日开始与结束时间的独立绝对偏移，当前默认窗口为 `14:00–22:00`、波动为 ±60 分钟；刷新和后台恢复不会重新抽取，到达实际结束时间后完成当前画廊或错误标签记录再停止领取新任务。
- 执行顺序：正常运行先扫描并转移 Tag，再检查 Repository 错误标签；主页会为错误标签阶段保留最小请求额度。
- 周期恢复：绝对截止时间、每日本地时间窗、持久队列、运行标记和跨标签页运行租约共同处理刷新、冻结和往返缓存恢复；不会每轮强制刷新页面。
- 错误标签：若仍有赞成票则先撤销再踩，标签或画廊已失效时保存终态；面板支持复查已知记录和导出本页会话最近 `1000` 条日志。
- 隐藏错误标签审计：每次读取 Repository 时同时记录错误画廊、完整链接、标题及长度、全部标签、错误标签与聚合频次；该快照不进入面板或控制台，只附加到 TXT，提供按频次排序的 TSV 和一行一个的黑名单候选区。
- 全局停止：任一 E-Hentai 或 ExHentai 生效页面点击“停止”都会通过 Tampermonkey 脚本存储通知两站所有标签页，刷新、跳转和新开页面继续保持停止，直到任一页面点击“重新开始”。

适用页面：

- `https://e-hentai.org/g/*/*`
- `https://exhentai.org/g/*/*`
- `https://e-hentai.org/`
- `https://exhentai.org/`

详情页需要同时存在画廊标题 `#gn` 和标签列表 `#taglist`；两站主页都需要位于根路径、存在 `.itg` 列表且不是搜索、翻页或日期范围页。

## 安装与升级

1. 安装 Tampermonkey 或兼容的用户脚本管理器。
2. 新建用户脚本，将 `eh-tag-transfer.js` 的完整内容粘贴并保存。
3. 同意脚本访问 `repo.e-hentai.org`；该权限只用于读取错误标签列表。
4. 打开或刷新 E-Hentai/ExHentai 主页或画廊详情页。右下角出现“跨语言 Tag 迁移”面板即表示加载成功。

升级时应完整替换旧内容，避免同时启用旧文件和 `eh-tag-transfer.js` 两个副本。每次版本变化都会重建主页队列并解除全局停止；保存新版本并刷新后可能按当前定时参数自动运行，不在每日窗口内时则等待下一个窗口。

## 使用方式

页面加载约 900 ms 后执行一次。详情页直接处理当前画廊；主页首次运行只建立当前列表基线，后续运行抓取主页并处理新增队列。若主页存在尚未到期的周期时间，重载后会按保存的绝对时间恢复而不是提前运行；若刷新发生在运行中，持久队列和运行标记会让新页面继续未完成工作。固定面板位于右下角，保留四个操作按钮、固定三行高且截断溢出内容的状态栏和最近 `20` 条关键日志。

- “停止”：终止当前读取、直连写入和后续提交，将停止状态写入 Tampermonkey 全局脚本存储，并同步暂停 E-Hentai 与 ExHentai 的所有生效页面；刷新、跳转、关闭当前页或新开页面都不会自动恢复。
- “重新开始”：清除全局停止状态并在当前页立即执行一轮，其他已打开页面只恢复后续调度，不会同时立即抢跑；手动运行不受每日时间窗限制，运行中按钮禁用，应先停止再开始。
- “重新检查错误标签”：忽略已知指纹过滤，立即重新检查 Repository 当前页的全部红色记录；该手动运行同样不受每日时间窗限制。
- “导出日志 TXT”：导出本次页面加载以来最多 `1000` 条会话日志，并附加修正状态审计、随机少迁移审计和最新的隐藏错误标签审计快照；刷新后这些会话数据都清空，不写入持久化存储。
- 所有运行参数只在脚本顶部 `SCRIPT_PARAMETERS` 中修改；旧 `config.v0` 不再读取，修改后重新保存 Tampermonkey 并刷新页面即可生效。

### 迁移设置

- 标签范围：源码默认 `solid`，只迁移实线标签；可改为 `all` 迁移全部标签。
- 迁移方向：源码默认 `newest`，完整读取所有通过复核的候选并综合旧画廊标签，只写入发布时间最新的一个目标；改为 `all` 时各版本互相补全，并继续使用同语言分差消歧。
- 随机少迁移：`randomTagSkipEnabled` 默认 `true`；`randomTagSkipMin`／`randomTagSkipMax` 默认 `0`／`3`，允许 `0–1000`，反向范围会自动交换。抽样池只包含经过黑名单、已有标签、当前赞成票、人工踩票和修正状态过滤后真正待提交的唯一标签；每任务只抽样一次并供全部目标复用，实际省略数不超过候选数减一。设为 `false` 可完全关闭。
- 搜索翻页上限：默认 `1`，允许 `1–5`，分别应用于英文查询和必要时执行的日文回退查询。
- 搜索请求间隔：默认 `3000` 毫秒，允许 `3000–60000`；读取重试也遵守该间隔。
- 最大页数差：默认 `3`，允许 `0–20`。
- 标题距离阈值：默认 `0.34`，允许 `0–1`。
- 候选最低分差：默认 `8`，允许 `0–50`，仅用于 `all` 互相补全模式；同语言多个候选的前两名分差不足时，该语言保持歧义并全部跳过。`newest` 单向模式改为综合所有通过完整复核的候选，不再按同语言择一。
- 短标题长度：默认 `15`，允许 `4–40`。短标题还必须具有相同作者、社团或标题署名证据。
- 最少画廊页数：默认 `10`，允许 `0–1000`；主页预览已给出页数时直接跳过，预览缺失时在读取详情后跳过，候选画廊也必须达到该值。
- 主页扫描页数：默认 `3`，允许 `1–10`；超过上限仍未遇到已知 GID 时保存 `#dnext` 游标，下轮从游标继续。
- 每轮请求上限：默认 `120`，允许 `10–200`；主页、搜索、详情、直连 POST、写后验证和错误标签请求共同计数，每次读取重试也单独计数。任何标签 POST 前必须至少还能容纳本次 POST 和一次写后 GET，预算不足时零写入并保留原任务；脚本连续查找下一个就绪任务，直到不足以安全开始新任务，预算边界不会增加失败次数或退避时间。
- 定时运行开始／结束时间：`scheduleStartTime` 与 `scheduleEndTime` 使用浏览器本地 `HH:mm`；默认 `14:00–22:00`，开始晚于结束表示跨午夜，两者相同表示全天。
- 定时启停波动：`scheduleTimeJitterMinutes` 默认 `60`，允许 `0–720`；每天对开始和结束分别均匀随机偏移，因此默认实际开始为 `13:00–15:00`、实际结束为 `21:00–23:00`，窄窗口会自动缩小有效波动以保证结束晚于开始，全天模式不产生启停波动。
- 黑名单：每行或逗号分隔一个规则，支持 `*` 通配符和以 `#` 开头的注释。带命名空间的规则匹配完整标签，如 `language:*` 和默认的 `other:multipanel sequence`；裸规则匹配任意命名空间下的标签名，如默认的 `full color`、`blowjob` 和本版新增的 `swimsuit`。
- `other:uncensored`：这是唯一采用目标专属策略的敏感标签，来源并集只能为明确无修正目标提供该标签；标题明确时即使没有同作品候选也可直接派生，不受 `solid/all` 影响，但仍受最少页数和黑名单约束。将 `uncensored` 或 `other:uncensored` 加入黑名单即可同时关闭来源迁移与标题派生。

标签范围、迁移方向、随机少迁移、周期、每日时间窗、错误标签开关、黑名单以及本节数值均不再显示于面板，全部集中在带逐项中文注释的源码参数区。

### 修正状态安全规则

- 分类器只读取 GN/GJ 的 `[]`、`()`、`【】` 元数据段，先做 NFKC、大小写和空白规范化，再使用包含匹配；裸标题正文不会参与修正状态判断。
- 正向词为 `Uncensored`、`Decensored`、`无修正/無修正`、`无码/無碼`、`去码/去碼`、`무수정`；否定词为 `Censored`、`有修正`、`有码/有碼`、`修正`、`モザイク`、`검열`、`모자이크`。较长的正向词会先消费匹配范围，因此 `Uncensored` 不会被内部的 `censored` 误判。
- `Not/Non`、`非/不是/不`、`ではない` 和 `아님/아닌` 等紧邻否定表达判为未知；GN/GJ 一边正向、一边否定时判为冲突。未知、冲突、明确有修正和未标注目标都不得接收来源的 `other:uncensored`。
- 当前任务画廊始终接受标题派生检查；形成迁移计划后，全部实际迁移目标也逐个检查并按 URL 去重。普通标签仍使用原并集，`newest` 的单向语义不会因为当前画廊也接受标题检查而反向迁移普通标签。
- 当前画廊和渐进详情候选保留本任务已取得的完整页面、标签状态及写入上下文；写入时不额外执行写前 GET，POST 后仍重新 GET 验证标签结果。任务运行期间若标题被外部修改，本版只验证标签结果，不自动撤票。
- 标题派生写入失败会记录警告但不单独保留主页任务；普通标签未确认仍按原有 `partial` 语义重试。已存在的历史错标不扫描、不撤赞也不踩，本补丁只防止新的错误迁移。

### 周期运行

- 默认开启。
- 周期固定参数默认 `3` 分钟，允许 `3–1440` 分钟；需停用时将源码参数 `scheduleEnabled` 改为 `false`。
- 每日自动运行窗口由 `scheduleStartTime`、`scheduleEndTime` 和 `scheduleTimeJitterMinutes` 控制，采用半开区间“实际开始时间（含）到实际结束时间（不含）”；跨午夜窗口可直接使用较晚的开始时间和较早的结束时间，起止相同表示全天。
- 每轮完成后加入约 ±10% 的随机抖动再安排下一轮。
- 每个逻辑日只生成一次实际起止绝对时间并保存在主页状态 v2 的 `scheduleWindow` 中，键包含日期、配置起止时间和波动参数；刷新、同源标签页和生命周期恢复复用该值，跨日或参数变化才重新生成。
- 周期时间若落在实际窗口外，会对齐到下一逻辑日的随机开始时间；达到实际结束时间时，当前扫描页、当前画廊及写后验证或当前错误标签记录先安全完成，随后不再领取新工作并跳过剩余自动阶段。未处于全局停止状态时，两项手动运行不受每日时间窗限制；全局停止后须先点击“重新开始”。
- 正常周期先执行主页扫描和 Tag 转移，再读取并处理错误标签；错误标签手动复查仍是独立运行。
- 主页模式把对齐后的 `nextRunAt` 和实际 `scheduleWindow` 一起持久化；30 秒生命周期心跳、`visibilitychange`、`focus`、`pageshow` 和 `resume` 都按绝对时间及当前窗口复核，后台冻结期间到期且仍在窗口内时补跑，窗口外则等待下一次开始。
- `freeze`、`pagehide` 或刷新前会中止当前请求并释放租约，队列任务不会提前删除；运行标记只用于区分“其他标签页已完成”和“上次运行被中断”，不检查登录 Session。
- 三种请求适配器都由共享生命周期内核执行 30 秒超时、外部 `AbortSignal` 取消、底层 `abort()` 和只结算一次；普通读取与 Repository 最多再做两次指数抖动重试，直连 POST 仍不自动重试，也不检测 Cloudflare 页面或重试永久 `4xx`（`408/425/429` 除外）。
- 未找到其他语言版本表示本次检查已经完成，该任务会移出队列；以后若出现新语言版本，新 GID 会重新触发搜索并找到旧版本。网络/页面异常或标签未全部确认时继续指数退避；请求预算到达边界时任务保持立即可运行且不累计失败。页面关闭或运行中断后，下一次主页运行会重新读取未完成任务；已经提交成功的标签会由现有实线或投票状态自动跳过。
- 每轮不会调用 `location.reload()`；周期扫描本身会重新请求主页。真实 `Ctrl+R`、`pageshow`、`focus` 和 `resume` 都使用持久化的 `nextRunAt` 恢复，避免强制刷新清空会话日志，同时承认真正被冻结的页面无法在冻结期间执行 JavaScript。
- 周期仍要求页面标签存在，浏览器关闭、标签页被丢弃或系统休眠时不是后台服务，也不保证精确到分钟。

### 错误标签检查

错误标签纠正使用与迁移相同的正式直连客户端；每次动作前读取最新状态，每次 POST 后重新 GET 验证结果。

- 默认开启，用户 UID 在脚本参数区默认为 `7647802`；需停用时将 `badTagEnabled` 改为 `false`。
- `uid` 只接受数字。启用后读取：
  `https://repo.e-hentai.org/tools/taglist?uid=<UID>&badtags=1`
- 首次检查会从当前第一页的红色记录开始处理，不再把启用前记录整页标成已知；`0.1.4.0` 使用新的 `v3` 状态键，因此旧版误建基线或只记录“标签已消失”的条目会重新进入待处理队列。
- 每轮最多处理 `10` 条，避免历史记录较多时长时间占用页面；剩余记录在后续周期继续处理。
- 已完成或明确无需再处理的终态记录才写入指纹。指纹由画廊 ID、规范英文标签和投票时间组成，因此同一画廊将来的新错误记录仍可被处理。
- 点击“重新检查错误标签”时会绕过已知指纹筛选，但仍按每轮 `10` 条分批复查当前页记录；失败记录可再次手动复查。
- 画廊 GET 返回 `404`、`410` 或明确失效页时记为“画廊已失效”；标签在初始检查、第一次写后验证或撤赞后验证中消失时记为“标签已不存在”。这些情况均保存为终态，不再提交投票。
- 若站点返回 `Your vote can no longer be withdrawn`，表示历史赞成票已被 E-Hentai 锁定，脚本会明确记录为无法更改的终态，避免每个周期无限重试；这种记录无法再撤赞或改踩。
- 标签带 `tup` 时直连发送一次 `vote=-1`，重新 GET 画廊确认赞成票已撤销；标签仍在且处于中立状态时，才发送第二次 `vote=-1` 并再次 GET 确认 `tdn`。任一验证阶段标签消失即按终态结束。
- 标签处于中立状态时直接发送一次 `vote=-1`；已经带 `tdn` 时视为此前已经踩过，不发送请求。
- 标签仍存在但画廊 HTML 缺少有效直连地址或动态凭据时不写入，记录为“投票接口暂不可用”并保留待处理状态，下一周期重新读取。
- 所有 POST 都不做网络层自动重试。响应丢失、超时或 JSON 不明时先重新 GET 验证；未确认标签在本轮记为失败，禁止立即重复投票，避免一次成功写入被第二次同值投票撤销。
- Repository 与普通 GET 对网络错误、超时、`408/425/429` 和 `5xx` 最多尝试三次；直连 POST 不套用该读取重试器。未知页面结构、写后状态未改变或凭据暂不可用时不写入已处理状态，下一周期会重新读取并判断。
- 只读取 Repository 当前返回的页面，不自动翻阅更旧分页。
- 错误标签检查和画廊迁移共用跨标签页运行租约，避免同源多个标签页同时写入；租约只负责跨页面互斥，不再把主页队列限制为每轮一个任务。
- Repository DOM 会在同一次遍历中生成纠正记录和隐藏审计快照。审计保留每个错误画廊的 GID、链接、标题、原始／规范标题长度、全部标签数、错误标签数、全部标签与带时间的错误标签；各错误标签另按“记录数、涉及画廊数”降序聚合，不改变既有纠正、指纹和投票流程。

### 日志与导出

- 每条错误标签结果日志都带 Repository 记录中的完整画廊 URL；面板将其渲染为新标签页打开的安全链接，控制台和 TXT 保留纯文本 URL。
- 搜索查询、预筛和候选详情只更新状态行，不累计到日志。日志只保留迁移／投票结果、错误、全局停止变化和每轮请求摘要。
- 面板 DOM 只保留最近 `20` 条关键日志以限制长期运行的渲染开销，脚本内存保留本页会话最近 `1000` 条供导出，刷新后清空。
- 页面处于后台时，日志继续写入内存但不修改日志 DOM；恢复可见后一次重绘最近 `20` 条。控制台只输出警告和错误。
- TXT 第一部分包含脚本版本、导出时间、当前站点、日志条数、ISO 时间、级别、消息和画廊 URL；第二部分为修正状态审计，记录目标 GN/GJ、命中词、分类、动作、原因及携带敏感标签的来源链接；第三部分为随机少迁移审计，记录时间、配置范围、候选数、实际省略数、完整省略标签列表和种子画廊链接；第四部分为隐藏错误标签审计，依次提供摘要、错误标签频次 TSV、可直接复制的一行一个黑名单候选、逐画廊明细与全部标签。文件使用 UTF-8 BOM 与 Windows CRLF，文件名格式为 `eh-tag-transfer-log-YYYYMMDD-HHmmss.txt`。

## 单文件模块分层

脚本仍是可直接安装的一个 userscript，主体依次划分为配置与运行状态、持久状态／预算／租约、标题与候选纯规则、统一请求生命周期与读取、直连写入与错误标签、四阶段搜索与迁移、定时调度／生命周期／UI、搜索阶段与测试入口。生产路径直接调用具名函数，不再经过 `REQUEST_CLIENT` 或 `SCHEDULER` 门面；Fetch、直连 XHR 与 Repository 仍共享 `runRequestLifecycle`，`SEARCH_PIPELINE` 只编排发现、预筛、渐进详情和最终选择。Node `CORE` 只按配置、匹配、搜索、迁移、Repository、写入协议、日志、主页、调度、请求和协调暴露高层测试接口，不承诺旧扁平字段兼容。

## 主页增量队列

1. 首次进入主页时解析当前 `.itg` 列表，将可识别 GID 写入 `seenGids`，不回溯或处理已有结果。
2. 后续运行从主页或持久化 `scanCursor` 开始，读取最多“主页扫描页数”，遇到运行前已经见过的 GID 即结束本次回溯。
3. 新 GID 只有在建立基线、明确因页数过短跳过或完整加入持久队列后才进入已见集合；待处理队列不再静默截断最老任务。
4. 持有跨标签页运行租约的执行器在已经规范化的内存队列中按顺序查找一个就绪任务，不再为每个任务复制和重新规范化整条队列；只在任务完成或失败结果确定后持久化一次，直到任务耗尽或剩余请求不足以安全开始下一个任务。
5. 同一轮发现的多个语言版本若被识别为一个关联组，会一起从队列移除；各 GID 已进入 `seenGids`，因此不需要再持久化一份从未读取的关联组记录。
6. 未找到其他语言版本会结束当前任务，因为未来新增的语言版本会以自己的 GID 重新触发搜索；网络失败或存在未确认标签时从 30 分钟开始退避，最高 24 小时；请求预算边界只暂停本轮，不改变任务的立即可运行状态。

主页扫描使用当前账号的站点过滤器，因此只发现主页实际可见的画廊。关联画廊搜索会显式忽略账号的语言、上传者和 My Tags 排除设置，避免正确候选被个人过滤器隐藏；上传者名称和 UID 仍不会进入查询文本、候选过滤或评分。

Repository 的标签列表只会在脚本实际提交标签投票时出现新记录；“没有其他语言版本”、目标标签已经实线或本轮只完成扫描都不会产生 Repository 记录。主页面板现在用“检查 / 写入 / 队列”分别显示本轮结果，判断周期是否执行应以日志中的“开始运行”、主页扫描结果和下次时间为准，不能要求每个周期都出现标签投票。

## 搜索与候选判定

### 标题解析

脚本以 [EHWiki Renaming](https://ehwiki.org/wiki/renaming) 的同人志命名顺序为基础：

- `(Convention) [Circle (Artist)] Title (Parody) [Language] [Translator] [Special Indicator]`
- `[Group (Artist)] Work (Parody) [Language] [Digital]`
- `(Event) [Group (Artist)] Work (Parody)`
- `[NENIGE] Work | 翻译标题 [Chinese] [Translator]`
- `[Torii Yoshitsuna] Work`
- 无方括号标题

页面的 `#gn` 作为英文／罗马字主标题字段，`#gj` 作为日文副标题字段。解析先做 NFKC 规范化，再清理开头的展会与署名、末尾语言／翻译／Digital 标记和原作段；展会与 Digital 仅作为非作品名清理，不保存为候选证据，也不产生加分、扣分或冲突。

章节不会再从搜索标题中丢弃。脚本将基础作品名与章节身份分开，支持 `Ch.`、`Chapter`、`Episode`、`Vol.`、`Volume`、`Part`、`Pt.`、`第…話/话/章/回/集/巻/卷/部`、`제…화`、前中后篇，以及 `Prologue`、`Epilogue`、`Interlude`、`Extra`、`Special`、`Bonus`、`Omake`；编号允许四位整数、小数、字母后缀和范围，因此 `Ch. 1-50` 或 `第1-50話` 会保留在搜索词中。双方都有章节身份且类型或范围不同时拒绝，只有一方缺失章节时继续依靠其他证据。

规则依据：

- [Renaming](https://ehwiki.org/wiki/renaming)：同人志字段顺序，以及 `Ch. 1-5`、`第1-5話`、`Vol. 8`、`第8巻` 等章节和卷数格式。
- [Making Galleries](https://ehwiki.org/wiki/Making_Galleries)：罗马音主标题为必填字段，日文标题在适用时提供。
- [Gallery Searching](https://ehwiki.org/wiki/Gallery_Searching)：站内标题匹配会同时使用罗马音与日文标题字段。

### 搜索

每次关联搜索按四个具名阶段顺序执行，并在面板状态行显示当前阶段：

1. **发现**：执行英文／罗马字查询，必要时回退日文查询，合并查询命中并按规范 URL 去重，同时提前排除具有相同显式语言标签的结果。
2. **预筛**：只使用列表预览中的标题、章节、页数和显式语言执行低成本判定，不读取候选详情。
3. **渐进详情**：`newest` 模式读取全部初筛合规候选，`all` 模式按语言和预览评分限制详情候选，再读取完整 `#gn/#gj/#taglist` 复核。
4. **最终选择**：根据迁移方向和最低分差产生接受／拒绝集合，随后才构造标签并集和写入计划。

阶段内部遵循以下请求规则：

1. 先从 `#gn` 生成一个 `title:"英文或罗马字标题"` 查询；只有结果中没有通过标题、章节、绝对页差和显式语言初筛的候选时，才从 `#gj` 生成一个日文查询。
2. 搜索 URL 固定携带 `f_sfl=on`、`f_sfu=on` 和 `f_sft=on`，只用于取消账号侧语言、上传者和 My Tags 排除设置，不会把上传者作为作品证据。
3. 不再生成去掉原作段的备用标题，也不再生成 `group:` 或 `artist:` 精炼查询；作者和社团只在候选验证中使用。
4. 搜索词使用清理后的基础标题并重新附加章节后缀，查询文本最长 `200` 字符；过长时优先截短基础标题，章节部分始终保留。
5. 搜索间隔由 `searchRequestIntervalMs` 控制，默认 `3000` 毫秒且不得低于 `3000` 毫秒，读取重试也遵守同一节流器。
6. 每个标题查询最多读取 `maxSearchPages` 页；无下一页、页面没有新 GID 或高辨识度标题已有强候选时提前停止。搜索结果按规范画廊 URL 去重，双方都有相同显式 `language:*` 标签时不再读取详情。

单个画廊正常只产生一次英文搜索，最多在没有合规候选时增加一次日文搜索。上传者可能转载、翻译或重新发布作品，不代表作品创作者，因此上传者名称和 UID 不进入查询、过滤或评分。

### 验证和评分

候选依次经过：

1. 排除当前画廊；搜索预览只在双方都带相同显式语言标签时提前排除同语言候选，标题推断语言不会用于提前拒绝。
2. 检查绝对页差和标题编辑距离；任一主/副标题字段可靠匹配即可提供标题身份依据，不再计算相对页差。
3. 标题两侧都有方括号署名但没有任何共同署名词时直接拒绝；该规则只使用标题本身，不会被此前误迁移进画廊的作者／社团标签反向污染。
4. 基础作品名中的独立阿拉伯编号集合必须一致；例如 `Boy Meets Girl` 不再匹配 `Boy Meets Girls 2`。双方都有明确章节身份时仍要求类型与编号相同，例如 `Ch. 12` 不会匹配 `Ch. 13`。
5. 短标题无论是否带有创作者标签，都必须找到共同标题署名或实线作者／社团；非完全相同的长标题还必须具有共同标题署名、实线作者／社团、明确章节或原作段之一作为独立身份依据。
6. 完整读取候选画廊的 `#gn` 与 `#gj`，再次验证双标题、页数和语言；两个对应字段都匹配时获得额外互证分。当双方都有实线作者或社团标签且互不相交，同时标题署名也无交集时，仍判为创作者冲突。
7. 通过硬门槛后再按最佳标题相似度、双标题互证、绝对页数接近度、章节一致性、作者/社团标签交集、标题署名、原作段和查询命中数评分；Digital 与展会文本不参与判定或评分。
8. `newest` 单向模式读取全部初筛合规候选的详情，完整复核后保留所有语言已确认的候选并作为旧画廊标签来源；`all` 互相补全模式仍为每种语言最多读取评分最高的 `3` 个详情，只接受明显首选，分差不足时保守跳过该语言。

同一轮搜索中的画廊对象和 `titleRefs` 都是不可变快照。脚本以 `WeakMap` 缓存标题身份与作者/社团集合，在预览停页、初筛和最终评分之间复用解析结果；任务对象释放后缓存条目可由浏览器自动回收，不形成跨周期常驻列表。

`0.2.5.0` 不改变上述任何接受、拒绝或评分结果。已批准的 C1 只负责目标专属的修正状态与 `other:uncensored` 安全过滤；后续 M2–M6 拟议规则、事故样本、正常翻译样本与潜在误伤单独列在 [后续匹配策略审查表](e-hentai-跨语言Tag迁移-匹配策略审查.md)，表中状态为“待批准”的项目在用户逐项确认前不得进入生产脚本。

## 标签迁移与提交验证

当前版本使用以下正式写入链路：

- “各版本互相补全”会合并当前画廊和所有已确认关联画廊的标签，并写入全部版本。
- “仅旧画廊 → 最新画廊”从详情页 `#gdd` 的 `Posted:` 读取发布时间，完整复核所有找到的合规候选，合并全部较旧画廊的标签并写入最新画廊；若发布时间缺失，以 GID 兜底。
- 默认仅使用实线标签，并应用黑名单。
- 写入目标时无条件复用本任务已经取得的完整画廊快照；只有缺少快照时才补读一次，并跳过已有实线标签、当前账号已投赞成票以及所有人工踩票标签。
- 所有目标完成专属规划后，脚本汇总真正待提交的唯一标签并只抽样一次；同一省略集合应用于每个目标。普通标签与来源或标题派生的 `other:uncensored` 都可被省略，省略不计失败、不触发 `partial` 或重试，错误标签纠正不经过这条路径。
- 根据 `#newtagfield` 的 `maxlength` 分批，直连 JSON 字段与站点一致：`method/apiuid/apikey/gid/token/tags/vote`。
- 每批 POST 后重新 GET 目标画廊并解析最新 `tup/tdn/gt/gtl` 状态；只有写后确认的标签计为成功。响应不明或仍未确认时本轮不再重投。
- 详情页和主页模式都使用相同的“任务快照 → POST → GET 写后验证”直连客户端，主页不会跳转，整个脚本运行期间 iframe 数量应始终为 `0`。
- “停止”会中止 `AbortController`、正在进行的 XHR/GET，并阻止后续批次。

脚本会按上述链路实际提交标签投票。首次启用或调整阈值后应检查面板日志，如候选不正确应立即点击“停止”，在脚本顶部参数区调整阈值并重新保存。

## 面板与状态保存

当前站点的 `localStorage` 使用以下键：

- `reina.ehTagTransfer.ui.v1`：仅作为旧版布局状态的兼容清理目标；固定式面板不再读取或写入该键。
- `reina.ehTagTransfer.badTags.v3`：当前 UID 和已处理错误标签指纹；旧对象中的初始化时间会在读取后自然丢弃。
- `reina.ehTagTransfer.home.v1`：主页基线、已见 GID、待处理队列、扫描游标、下次运行时间和内部状态版本；`0.1.6.2` 首次读取旧状态时会清理过去因“尚未找到其他语言版本”而永久退避的任务，同时保留网络失败和未确认标签任务，存储键不变。
- `reina.ehTagTransfer.workerLock.v1`：带到期时间和心跳的跨标签页运行租约，覆盖扫描、错误标签和迁移写入；存储键为兼容旧状态而保持不变。
- `reina.ehTagTransfer.runMarker.v1`：当前运行持有者和开始时间，仅用于刷新、冻结或标签页崩溃后的中断判定。

`home.v1` 会在扫描、任务完成或失败结果确定后保存，`badTags.v3` 只保存已确认终态的错误标签指纹；请求预算中断不会把任务写成失败或提前移出队列。

Tampermonkey 脚本存储使用 `reina.ehTagTransfer.globalPause.v1` 保存带修改时间的全局停止状态，并使用 `reina.ehTagTransfer.version.v1` 保存当前脚本版本及已完成重建的站点。两者都不属于网页 `localStorage`：停止状态由 E-Hentai、ExHentai、刷新后的页面和新标签页共享，值变化由 `GM_addValueChangeListener` 实时通知现存页面；版本变化时每个站点分别清除主页队列、扫描基线、调度窗口、下次运行时间、租约、运行标记和旧 UI 状态，首次发现新版本的页面同时解除全局停止。`badTags.v3` 的 UID 与历史指纹保留，错误标签审计仍只保留当前页面会话的最新快照。

E-Hentai 与 ExHentai 是不同源，因此历史记录、队列和锁分别保存；运行配置完全来自同一份脚本源码，不再按站点保存。E-Hentai 同源多标签页由 Worker 租约互斥；若两站同时开启错误标签检查，仍可能各执行一次，建议只在其中一个站点长期保留主页标签页，或在源码参数区关闭错误标签检查后按需手动复查。

## 权限与隐私

用户脚本元数据：

- `@match`：匹配 E-Hentai 与 ExHentai 两站主页和画廊详情页；脚本内部再排除搜索、翻页和范围页面。
- `@grant GM_xmlhttpRequest`：跨源读取 E-Hentai Tag Repository 的错误标签页。
- `@grant GM_getValue`、`GM_setValue`、`GM_addValueChangeListener`：在同一用户脚本的 E-Hentai／ExHentai 页面间读取、写入并同步全局停止状态；不读取其他脚本的数据。
- `@connect repo.e-hentai.org`：把跨源访问限制到该域名。
- `@run-at document-end`：主要 DOM 可用后初始化。
- `@noframes`：作为额外约束，防止脚本被第三方页面以子框架方式重复注入；当前实现本身不创建 iframe。

脚本不存储密码、Cookie 或动态画廊凭据，也不会把抓包内容写入源码、日志、夹具或配置。`apiuid/apikey/gid/token/api_url` 只从每次最新画廊 HTML 读取，在当前调用栈内用于一次写入；日志和持久状态均不包含这些值。源码参数区只包含用户明确指定且可编辑的 Repository `uid: '7647802'` 与标签黑名单；错误标签列表和画廊操作使用当前浏览器会话。

## 已知限制

- 搜索结果、标题、标签或站点 DOM 发生变化后，选择器和评分可能需要调整。
- 标题与评分只能降低误判，不能数学证明两个画廊属于同一作品。本版新增标题署名、基础作品编号和独立身份依据硬门槛，专门阻止 `4112860`／`1478533` 这类近似标题事故；如果站点标题本身缺少或写错这些信息，脚本会优先产生漏匹配而不是冒险写入。
- `newest` 单向模式会综合所有通过完整复核的候选，能减少漏标，但仍应检查“接受”与“单向迁移”日志；`all` 互补模式仍为每种语言只选择一个明显首选，分差不足时需要人工处理。若还要进一步提高确定性，可考虑首图感知哈希或人工确认，但前者增加图片请求与带宽，后者不适合无人值守，因此当前未启用。
- 修正状态分类只使用标题括号元数据，不尝试从图片内容或来源多数票推断；发布者未写标记时会保守漏加 `other:uncensored`。本任务按减少请求的既定选择复用任务内详情快照，不在 POST 前再次读取标题，写后也只验证标签；若标题恰在任务运行期间被外部修改，脚本只记录当次结果，不自动撤票。
- 当前脚本不扫描或纠正此前已经误加的 `other:uncensored`；如需立即停用来源迁移和标题派生，可把 `uncensored` 加入黑名单，既有标签仍需人工处理。
- 随机省略结果不持久化；刷新、失败重试或手动重新运行同一任务时会重新抽样，因此此前省略的标签以后可能被补上。计数以唯一标签名为单位，同一任务全部目标共享省略集合。
- 错误标签检查依赖 Repository 把错误标签显示为内联红色；对仍可见的标签依赖画廊页现有的 `tup/tdn` 类名、内联动态凭据和官方 `taggallery` JSON 响应。站点若更改这些字段、API 地址或投票切换语义，需要同步适配；脚本会因凭据校验失败而停止写入，不会回退 iframe。
- 错误标签一次只读取 Repository 当前返回的页面并每轮处理 `10` 条；更旧分页仍需由 Repository 页面或后续记录变化带入当前页。
- 隐藏错误标签审计同样只覆盖 Repository 当前返回页，并只保留本页会话最新快照；刷新后清空，导出前应至少完成一次自动检查或手动复查。
- 主页只发现当前站点过滤器可见的结果；切换过滤器后，以前不可见但尚未记录的旧画廊会被视为新发现。
- 用户脚本定时器依赖主页或详情页标签存在，不能代替浏览器扩展后台服务；Chrome 真正冻结页面时 JavaScript 本身无法执行，但页面即使在隐藏状态收到 `resume` 也会按绝对时间补跑，标签页被永久关闭或浏览器直接丢弃后仍不会自行重开。
- E-Hentai 与 ExHentai 的业务队列和 Worker 租约仍在各自 `localStorage` 中，跨域同时启用时不能依靠单个租约互斥；但“停止／重新开始”状态已经改用 Tampermonkey 全局脚本存储，两站、刷新和新标签页会共享该状态。
