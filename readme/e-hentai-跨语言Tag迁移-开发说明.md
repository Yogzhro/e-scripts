# E-Hentai 跨语言画廊 Tag 迁移

- 主脚本：`eh-tag-transfer.js`
- 作者：`wakuwaku`
- 当前版本：`0.1.8.5`

## 用途

脚本既可在 E-Hentai 或 ExHentai 画廊详情页处理当前作品，也可停留在两站主页增量发现新画廊。主页只负责发现和排队；标题、页数、语言、标签状态与写入仍在后台读取完整详情页后验证，用户不需要逐个打开画廊。

当前版本的主要行为：

- 主页队列：首次运行只记录当前列表为基线，以后按 GID 去重并持久化排队；每轮在请求预算内连续处理全部就绪任务，不再固定只取一个画廊，也不会以 `500` 条静默截断队列。
- 两级搜索：先用 `#gn` 英文／罗马字标题搜索，只有没有合规候选时才用 `#gj` 日文标题回退；不再生成备用标题、作者或社团精炼查询。
- 章节身份：识别 `Ch.`、`Chapter`、`Vol.`、`Episode`、`Part`、`第…話/巻`、韩文章节和特殊章节等后缀，搜索词保留章节，候选双方章节明确冲突时拒绝。
- 候选验证：只使用绝对页差，不再检查相对页差；Digital 与展会信息会从核心标题中清理，但不再参与候选验证和评分。
- 请求控制：搜索间隔由源码参数 `searchRequestIntervalMs` 配置，默认与下限均为 `3000` 毫秒；主页总请求上限默认 `80`。
- 完全直连：读取画廊 HTML 中站点提供的 `api_url/apiuid/apikey/gid/token`，通过官方 `taggallery` JSON 协议写入；脚本不再创建隐藏 iframe，也不再点击标签菜单或调用页面 `send_vote`。
- 真实写入：`0.1.8.2` 已完整移除临时只读演练层，迁移、错误标签纠正、主页队列和终态指纹均恢复正式行为；写入仍由中央直连客户端统一执行并在每次 POST 后重新读取验证。
- 源码可读性：`0.1.8.3` 将压缩主体恢复为带换行和四空格缩进的可读排版；参数名、默认值、中文注释、分支、接口和写入行为均未修改。
- 统一测试：`0.1.8.4` 新增一个无第三方依赖的测试入口，顺序执行语法检查、核心测试、主页 30 分钟模拟、正式模式与源码排版审计，以及自动启停的本地夹具 HTTP 烟测；同一入口也可启动 Chrome 人工夹具。
- 语义命名：`0.1.8.5` 将 Terser 混淆留下的顶层、函数参数、局部变量、回调、循环和异常分支短名称恢复为按当前逻辑重建的语义名称，并加入全文件残余审计；由于 `0.1.8.0` 未保留 source map，这些名称不能证明与压缩前源码逐字相同，但运行语义没有变化。
- 执行顺序：正常运行先扫描并转移 Tag，再检查 Repository 错误标签；主页会为错误标签阶段保留最小请求额度。
- 周期恢复：绝对截止时间、持久队列、运行标记和跨标签页运行租约共同处理刷新、冻结和往返缓存恢复；不会每轮强制刷新页面。
- 错误标签：若仍有赞成票则先撤销再踩，标签或画廊已失效时保存终态；面板支持复查已知记录和导出本页会话最近 `1000` 条日志。

适用页面：

- `https://e-hentai.org/g/*/*`
- `https://exhentai.org/g/*/*`
- `https://e-hentai.org/`
- `https://exhentai.org/`

详情页需要同时存在画廊标题 `#gn` 和标签列表 `#taglist`；两站主页都需要位于根路径、存在 `.itg` 列表且不是搜索、翻页或日期范围页。

## 安装与升级

1. 安装 Tampermonkey 或兼容的用户脚本管理器。
2. 新建用户脚本，将 `eh-tag-transfer.js` 的完整内容粘贴并保存。
3. 同意脚本访问 `repo.e-hentai.org`；该权限只用于读取错误标签列表。
4. 打开或刷新 E-Hentai/ExHentai 主页或画廊详情页。右上角出现“跨语言 Tag 迁移”面板即表示加载成功。

升级时应完整替换旧内容，避免同时启用旧文件和 `eh-tag-transfer.js` 两个副本。

## 使用方式

页面加载约 900 ms 后执行一次。详情页直接处理当前画廊；主页首次运行只建立当前列表基线，后续运行抓取主页并处理新增队列。若主页存在尚未到期的周期时间，重载后会按保存的绝对时间恢复而不是提前运行；若刷新发生在运行中，持久队列和运行标记会让新页面继续未完成工作。面板支持拖动、最小化并保存位置与折叠状态，运行状态、主页队列摘要和详细日志统一显示在同一个日志区域。

- “停止”：终止当前读取、直连写入和后续提交，同时暂停已安排的周期运行。
- “重新开始”：恢复周期调度并立即执行一轮；运行中按钮禁用，应先停止再开始。
- “重新检查错误标签”：忽略已知指纹过滤，重新检查 Repository 当前页的全部红色记录，并按撤赞、再踩和操作后验证规则执行。
- “导出日志 TXT”：导出本次页面加载以来最多 `1000` 条日志；刷新后日志历史清空，不写入持久化存储。
- 所有运行参数只在脚本顶部 `SCRIPT_PARAMETERS` 中修改；旧 `config.v0` 不再读取，修改后重新保存 Tampermonkey 并刷新页面即可生效。

### 迁移设置

- 标签范围：源码默认 `solid`，只迁移实线标签；可改为 `all` 迁移全部标签。
- 迁移方向：源码默认 `newest`，完整读取所有通过复核的候选并综合旧画廊标签，只写入发布时间最新的一个目标；改为 `all` 时各版本互相补全，并继续使用同语言分差消歧。
- 搜索翻页上限：默认 `1`，允许 `1–5`，分别应用于英文查询和必要时执行的日文回退查询。
- 搜索请求间隔：默认 `3000` 毫秒，允许 `3000–60000`；读取重试也遵守该间隔。
- 最大页数差：默认 `3`，允许 `0–20`。
- 标题距离阈值：默认 `0.34`，允许 `0–1`。
- 候选最低分差：默认 `8`，允许 `0–50`，仅用于 `all` 互相补全模式；同语言多个候选的前两名分差不足时，该语言保持歧义并全部跳过。`newest` 单向模式改为综合所有通过完整复核的候选，不再按同语言择一。
- 短标题长度：默认 `15`，允许 `4–40`。短标题还必须具有相同作者、社团或标题署名证据。
- 最少画廊页数：默认 `10`，允许 `0–1000`；主页预览已给出页数时直接跳过，预览缺失时在读取详情后跳过，候选画廊也必须达到该值。
- 主页扫描页数：默认 `3`，允许 `1–10`；超过上限仍未遇到已知 GID 时保存 `#dnext` 游标，下轮从游标继续。
- 每轮请求上限：默认 `80`，允许 `10–200`；主页、搜索、详情、直连 POST、写后验证和错误标签请求共同计数，每次读取重试也单独计数。脚本连续查找下一个就绪任务，直到不足以安全开始新任务；预算在任务中途达到边界时不保存临时“开始”状态，原任务保持立即可运行且不增加失败次数或退避时间。
- 黑名单：每行或逗号分隔一个规则，支持 `*` 通配符和以 `#` 开头的注释。带命名空间的规则匹配完整标签，如 `language:*`；裸规则匹配标签名，如 `blowjob`。

标签范围、迁移方向、周期与错误标签开关、黑名单以及本节数值均不再显示于面板，全部集中在带逐项中文注释的源码参数区。

### 周期运行

- 默认开启。
- 周期固定参数默认 `3` 分钟，允许 `3–1440` 分钟；需停用时将源码参数 `scheduleEnabled` 改为 `false`。
- 每轮完成后加入约 ±10% 的随机抖动再安排下一轮。
- 正常周期先执行主页扫描和 Tag 转移，再读取并处理错误标签；错误标签手动复查仍是独立运行。
- 主页模式把 `nextRunAt` 持久化；30 秒生命周期心跳、`visibilitychange`、`focus`、`pageshow` 和 `resume` 都按绝对时间复核，后台冻结期间错过的周期会在 `resume` 时补跑，即使恢复事件发生时标签页仍然隐藏。
- `freeze`、`pagehide` 或刷新前会中止当前请求并释放租约，队列任务不会提前删除；运行标记只用于区分“其他标签页已完成”和“上次运行被中断”，不检查登录 Session。
- 读取请求有 30 秒超时和最多两次指数抖动重试，不检测 Cloudflare 页面，也不重试 `4xx` 永久错误（`408/425/429` 除外）。
- 未找到其他语言版本表示本次检查已经完成，该任务会移出队列；以后若出现新语言版本，新 GID 会重新触发搜索并找到旧版本。网络/页面异常或标签未全部确认时继续指数退避；请求预算到达边界时任务保持立即可运行且不累计失败。页面关闭或运行中断后，下一次主页运行会重新读取未完成任务；已经提交成功的标签会由现有实线或投票状态自动跳过。
- 每轮不会调用 `location.reload()`；周期扫描本身会重新请求主页。真实 `Ctrl+R`、`pageshow`、`focus` 和 `resume` 都使用持久化的 `nextRunAt` 恢复，避免强制刷新清空会话日志，同时承认真正被冻结的页面无法在冻结期间执行 JavaScript。
- 周期仍要求页面标签存在，浏览器关闭、标签页被丢弃或系统休眠时不是后台服务，也不保证精确到分钟。

### 错误标签检查

错误标签纠正使用与迁移相同的正式直连客户端；每次动作前读取最新状态，每次 POST 后重新 GET 验证结果。

- 默认开启，用户 UID 在脚本参数区默认为 `7647802`；需停用时将 `badTagEnabled` 改为 `false`。
- `uid` 只接受数字。启用后读取：
  `https://repo.e-hentai.org/tools/taglist?uid=<UID>&badtags=1`
- 首次检查会从当前第一页的红色记录开始处理，不再把启用前记录整页标成已知；`0.1.4.0` 使用新的 `v3` 状态键，因此旧版误建基线或只记录“标签已消失”的条目会重新进入待处理队列。
- 每轮最多处理 `10` 条，避免历史记录较多时长时间占用页面；剩余记录在后续周期继续处理。
- 已完成或明确无需再处理的终态记录才写入指纹。指纹由画廊 ID、规范英文标签和投票时间组成，因此同一画廊将来的新错误记录仍可被处理。
- 点击“重新检查错误标签”时会绕过已知指纹筛选，但仍按每轮 `10` 条分批复查当前页记录；失败记录可再次手动复查。
- 画廊 GET 返回 `404`、`410` 或明确失效页时记为“画廊已失效”；标签在初始检查、第一次写后验证或撤赞后验证中消失时记为“标签已不存在”。这些情况均保存为终态，不再提交投票。
- 若站点返回 `Your vote can no longer be withdrawn`，表示历史赞成票已被 E-Hentai 锁定，脚本会明确记录为无法更改的终态，避免每个周期无限重试；这种记录无法再撤赞或改踩。
- 标签带 `tup` 时直连发送一次 `vote=-1`，重新 GET 画廊确认赞成票已撤销；标签仍在且处于中立状态时，才发送第二次 `vote=-1` 并再次 GET 确认 `tdn`。任一验证阶段标签消失即按终态结束。
- 标签处于中立状态时直接发送一次 `vote=-1`；已经带 `tdn` 时视为此前已经踩过，不发送请求。
- 标签仍存在但画廊 HTML 缺少有效直连地址或动态凭据时不写入，记录为“投票接口暂不可用”并保留待处理状态，下一周期重新读取。
- 所有 POST 都不做网络层自动重试。响应丢失、超时或 JSON 不明时先重新 GET 验证；未确认标签在本轮记为失败，禁止立即重复投票，避免一次成功写入被第二次同值投票撤销。
- Repository 与普通 GET 对网络错误、超时、`408/425/429` 和 `5xx` 最多尝试三次；直连 POST 不套用该读取重试器。未知页面结构、写后状态未改变或凭据暂不可用时不写入已处理状态，下一周期会重新读取并判断。
- 只读取 Repository 当前返回的页面，不自动翻阅更旧分页。
- 错误标签检查和画廊迁移共用跨标签页运行租约，避免同源多个标签页同时写入；租约只负责跨页面互斥，不再把主页队列限制为每轮一个任务。

### 日志与导出

- 每条错误标签结果日志都带 Repository 记录中的完整画廊 URL；面板将其渲染为新标签页打开的安全链接，控制台和 TXT 保留纯文本 URL。
- 当前运行状态、主页队列摘要和最近日志共用一个深色日志区域，避免同类运行信息分散在面板不同区块。
- 面板 DOM 只保留最近 `100` 条以限制长期运行的渲染开销，脚本内存保留本页会话最近 `1000` 条供导出，刷新后清空。
- 页面处于后台或面板最小化时，日志继续写入内存但不修改日志 DOM；恢复可见或展开面板后一次重绘最近 `100` 条。控制台只输出警告和错误。
- TXT 包含脚本版本、导出时间、当前站点、日志条数、ISO 时间、级别、消息和画廊 URL，使用 UTF-8 BOM 与 Windows CRLF，文件名格式为 `eh-tag-transfer-log-YYYYMMDD-HHmmss.txt`。

## 主页增量队列

1. 首次进入主页时解析当前 `.itg` 列表，将可识别 GID 写入 `seenGids`，不回溯或处理已有结果。
2. 后续运行从主页或持久化 `scanCursor` 开始，读取最多“主页扫描页数”，遇到运行前已经见过的 GID 即结束本次回溯。
3. 新 GID 只有在建立基线、明确因页数过短跳过或完整加入持久队列后才进入已见集合；待处理队列不再静默截断最老任务。
4. 持有跨标签页运行租约的执行器在已经规范化的内存队列中按顺序查找一个就绪任务，不再为每个任务复制和重新规范化整条队列；只在任务完成或失败结果确定后持久化一次，直到任务耗尽或剩余请求不足以安全开始下一个任务。
5. 同一轮发现的多个语言版本若被识别为一个关联组，会一起从队列移除；各 GID 已进入 `seenGids`，因此不需要再持久化一份从未读取的关联组记录。
6. 未找到其他语言版本会结束当前任务，因为未来新增的语言版本会以自己的 GID 重新触发搜索；网络失败或存在未确认标签时从 30 分钟开始退避，最高 24 小时；请求预算边界只暂停本轮，不改变任务的立即可运行状态。

主页扫描使用当前账号的站点过滤器，因此只发现主页实际可见的画廊。关联画廊搜索会显式忽略账号的语言、上传者和 My Tags 排除设置，避免正确候选被个人过滤器隐藏；上传者名称和 UID 仍不会进入查询文本、候选过滤或评分。

Repository 的标签列表只会在脚本实际提交标签投票时出现新记录；“没有其他语言版本”、目标标签已经实线或本轮只完成扫描都不会产生 Repository 记录。主页面板现在用“检查 / 写入 / 队列”分别显示本轮结果，判断周期是否执行应以日志中的“开始运行”、主页扫描结果和下次时间为准，不能要求每个周期都出现标签投票。

## 搜索与候选判定

### 标题解析

脚本以 [EHWiki Renaming](https://ehwiki.org/wiki/renaming) 的同人志命名顺序为基础：

- `(Convention) [Circle (Artist)] Title (Parody) [Language] [Translator] [Special Indicator]`
- `[Group (Artist)] Work (Parody) [Language] [Digital]`
- `(Event) [Group (Artist)] Work (Parody)`
- `[NENIGE] Work | 翻译标题 [Chinese] [Translator]`
- `[Torii Yoshitsuna] Work`
- 无方括号标题

页面的 `#gn` 作为英文／罗马字主标题字段，`#gj` 作为日文副标题字段。解析先做 NFKC 规范化，再清理开头的展会与署名、末尾语言／翻译／Digital 标记和原作段；展会与 Digital 仅作为非作品名清理，不保存为候选证据，也不产生加分、扣分或冲突。

章节不会再从搜索标题中丢弃。脚本将基础作品名与章节身份分开，支持 `Ch.`、`Chapter`、`Episode`、`Vol.`、`Volume`、`Part`、`Pt.`、`第…話/话/章/回/集/巻/卷/部`、`제…화`、前中后篇，以及 `Prologue`、`Epilogue`、`Interlude`、`Extra`、`Special`、`Bonus`、`Omake`；编号允许四位整数、小数、字母后缀和范围，因此 `Ch. 1-50` 或 `第1-50話` 会保留在搜索词中。双方都有章节身份且类型或范围不同时拒绝，只有一方缺失章节时继续依靠其他证据。

规则依据：

- [Renaming](https://ehwiki.org/wiki/renaming)：同人志字段顺序，以及 `Ch. 1-5`、`第1-5話`、`Vol. 8`、`第8巻` 等章节和卷数格式。
- [Making Galleries](https://ehwiki.org/wiki/Making_Galleries)：罗马音主标题为必填字段，日文标题在适用时提供。
- [Gallery Searching](https://ehwiki.org/wiki/Gallery_Searching)：站内标题匹配会同时使用罗马音与日文标题字段。

### 搜索

1. 先从 `#gn` 生成一个 `title:"英文或罗马字标题"` 查询；只有结果中没有通过标题、章节、绝对页差和显式语言初筛的候选时，才从 `#gj` 生成一个日文查询。
2. 搜索 URL 固定携带 `f_sfl=on`、`f_sfu=on` 和 `f_sft=on`，只用于取消账号侧语言、上传者和 My Tags 排除设置，不会把上传者作为作品证据。
3. 不再生成去掉原作段的备用标题，也不再生成 `group:` 或 `artist:` 精炼查询；作者和社团只在候选验证中使用。
4. 搜索词使用清理后的基础标题并重新附加章节后缀，查询文本最长 `200` 字符；过长时优先截短基础标题，章节部分始终保留。
5. 搜索间隔由 `searchRequestIntervalMs` 控制，默认 `3000` 毫秒且不得低于 `3000` 毫秒，读取重试也遵守同一节流器。
6. 每个标题查询最多读取 `maxSearchPages` 页；无下一页、页面没有新 GID 或高辨识度标题已有强候选时提前停止。搜索结果按规范画廊 URL 去重，双方都有相同显式 `language:*` 标签时不再读取详情。

单个画廊正常只产生一次英文搜索，最多在没有合规候选时增加一次日文搜索。上传者可能转载、翻译或重新发布作品，不代表作品创作者，因此上传者名称和 UID 不进入查询、过滤或评分。

### 验证和评分

候选依次经过：

1. 排除当前画廊；搜索预览只在双方都带相同显式语言标签时提前排除同语言候选，标题推断语言不会用于提前拒绝。
2. 检查绝对页差和标题编辑距离；任一主/副标题字段可靠匹配即可提供标题身份依据，不再计算相对页差。
3. 双方都有明确章节身份时要求类型与编号相同；例如 `Ch. 12` 不会匹配 `Ch. 13`，只有一方缺失章节信息时保持中立。
4. 完整读取候选画廊的 `#gn` 与 `#gj`，再次验证双标题、页数和语言；两个对应字段都匹配时获得额外互证分。
5. 当双方都有实线作者或社团标签且互不相交，同时标题署名也无交集时，判为创作者冲突。
6. 按最佳标题相似度、双标题互证、绝对页数接近度、章节一致性、作者/社团标签交集、标题署名、原作段和查询命中数评分；Digital 与展会文本不参与判定或评分。
7. `newest` 单向模式读取全部初筛合规候选的详情，完整复核后保留所有语言已确认的候选并作为旧画廊标签来源；`all` 互相补全模式仍为每种语言最多读取评分最高的 `3` 个详情，只接受明显首选，分差不足时保守跳过该语言。

同一轮搜索中的画廊对象和 `titleRefs` 都是不可变快照。脚本以 `WeakMap` 缓存标题身份与作者/社团集合，在预览停页、初筛和最终评分之间复用解析结果；任务对象释放后缓存条目可由浏览器自动回收，不形成跨周期常驻列表。

## 标签迁移与提交验证

当前版本使用以下正式写入链路：

- “各版本互相补全”会合并当前画廊和所有已确认关联画廊的标签，并写入全部版本。
- “仅旧画廊 → 最新画廊”从详情页 `#gdd` 的 `Posted:` 读取发布时间，完整复核所有找到的合规候选，合并全部较旧画廊的标签并写入最新画廊；若发布时间缺失，以 GID 兜底。
- 默认仅使用实线标签，并应用黑名单。
- 写入目标前再次读取目标画廊；跳过已有实线标签和当前账号已投赞成票的标签。
- 根据 `#newtagfield` 的 `maxlength` 分批，直连 JSON 字段与站点一致：`method/apiuid/apikey/gid/token/tags/vote`。
- 每批 POST 后重新 GET 目标画廊并解析最新 `tup/tdn/gt/gtl` 状态；只有写后确认的标签计为成功。响应不明或仍未确认时本轮不再重投。
- 详情页和主页模式都使用相同的 GET → 验证 → POST → GET 直连客户端，主页不会跳转，整个脚本运行期间 iframe 数量应始终为 `0`。
- “停止”会中止 `AbortController`、正在进行的 XHR/GET，并阻止后续批次。

脚本会按上述链路实际提交标签投票。首次启用或调整阈值后应检查面板日志，如候选不正确应立即点击“停止”，在脚本顶部参数区调整阈值并重新保存。

## 面板与状态保存

当前站点的 `localStorage` 使用以下键：

- `reina.ehTagTransfer.ui.v1`：面板位置和最小化状态。
- `reina.ehTagTransfer.badTags.v3`：当前 UID 和已处理错误标签指纹；旧对象中的初始化时间会在读取后自然丢弃。
- `reina.ehTagTransfer.home.v1`：主页基线、已见 GID、待处理队列、扫描游标、下次运行时间和内部状态版本；`0.1.6.2` 首次读取旧状态时会清理过去因“尚未找到其他语言版本”而永久退避的任务，同时保留网络失败和未确认标签任务，存储键不变。
- `reina.ehTagTransfer.workerLock.v1`：带到期时间和心跳的跨标签页运行租约，覆盖扫描、错误标签和迁移写入；存储键为兼容旧状态而保持不变。
- `reina.ehTagTransfer.runMarker.v1`：当前运行持有者和开始时间，仅用于刷新、冻结或标签页崩溃后的中断判定。

`home.v1` 会在扫描、任务完成或失败结果确定后保存，`badTags.v3` 只保存已确认终态的错误标签指纹；请求预算中断不会把任务写成失败或提前移出队列。

E-Hentai 与 ExHentai 是不同源，因此历史记录、队列和锁分别保存；运行配置完全来自同一份脚本源码，不再按站点保存。E-Hentai 同源多标签页由 Worker 租约互斥；若两站同时开启错误标签检查，仍可能各执行一次，建议只在其中一个站点长期保留主页标签页，或在源码参数区关闭错误标签检查后按需手动复查。

## 权限与隐私

用户脚本元数据：

- `@match`：匹配 E-Hentai 与 ExHentai 两站主页和画廊详情页；脚本内部再排除搜索、翻页和范围页面。
- `@grant GM_xmlhttpRequest`：跨源读取 E-Hentai Tag Repository 的错误标签页。
- `@connect repo.e-hentai.org`：把跨源访问限制到该域名。
- `@run-at document-end`：主要 DOM 可用后初始化。
- `@noframes`：作为额外约束，防止脚本被第三方页面以子框架方式重复注入；当前实现本身不创建 iframe。

脚本不存储密码、Cookie 或动态画廊凭据，也不会把抓包内容写入源码、日志、夹具或配置。`apiuid/apikey/gid/token/api_url` 只从每次最新画廊 HTML 读取，在当前调用栈内用于一次写入；日志和持久状态均不包含这些值。源码参数区只包含用户明确指定且可编辑的 Repository `uid: '7647802'` 与标签黑名单；错误标签列表和画廊操作使用当前浏览器会话。

## 从参考实现借鉴的思路

### `reference/eh漫画语言快捷按钮-0.7.js`

- 借鉴单倒计时器、运行中防重入和 `finally` 后统一重排下一周期的思路。
- 浏览器脚本不使用 Puppeteer、硬编码凭据、反检测参数或外部进程。

- 借鉴刷新前保存必要运行状态、恢复后校验完整性，以及用进度看门狗重新核对任务的思路。

### `reference/wawawa.js`

- 借鉴 Pointer Events 拖动悬浮面板，以及位置、展开状态的持久化。
- 本项目额外加入最小化、视口边界限制和窗口缩放后的回收定位。

## 已知限制

- 搜索结果、标题、标签或站点 DOM 发生变化后，选择器和评分可能需要调整。
- 标题与评分只能降低误判，不能数学证明两个画廊属于同一作品。
- `newest` 单向模式会综合所有通过完整复核的候选，能减少漏标，但候选误判也会把错误标签带入最新画廊；首次调整阈值后应重点检查“接受”与“单向迁移”日志。`all` 互补模式仍为每种语言只选择一个明显首选，分差不足时需要人工处理。
- 错误标签检查依赖 Repository 把错误标签显示为内联红色；对仍可见的标签依赖画廊页现有的 `tup/tdn` 类名、内联动态凭据和官方 `taggallery` JSON 响应。站点若更改这些字段、API 地址或投票切换语义，需要同步适配；脚本会因凭据校验失败而停止写入，不会回退 iframe。
- 错误标签一次只读取 Repository 当前返回的页面并每轮处理 `10` 条；更旧分页仍需由 Repository 页面或后续记录变化带入当前页。
- 主页只发现当前站点过滤器可见的结果；切换过滤器后，以前不可见但尚未记录的旧画廊会被视为新发现。
- 用户脚本定时器依赖主页或详情页标签存在，不能代替浏览器扩展后台服务；Chrome 真正冻结页面时 JavaScript 本身无法执行，但页面即使在隐藏状态收到 `resume` 也会按绝对时间补跑，标签页被永久关闭或浏览器直接丢弃后仍不会自行重开。
- E-Hentai 与 ExHentai 的 `localStorage` 不共享，跨域同时启用时不能依靠单个租约互斥。
