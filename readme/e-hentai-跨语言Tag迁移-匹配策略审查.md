# E-Hentai 跨语言 Tag 迁移：后续匹配策略审查表

- 审查基线：当前生产版 `0.2.5.0`（候选匹配行为与 `0.2.4.1` 相同）
- 原则：宁可漏配，也不误配
- 当前状态：C1 已批准并在 `0.2.4.1` 实施；M2–M6 仍为提案

## 审查方式

每项待批准提案必须由用户明确批准后才可实现。批准时可以指定适用范围、阈值或附加例外；未批准项目保持当前生产行为。实施期间若发现表外边界，必须重新提交审查，不得自行扩大规则。`0.2.5.0` 只增加迁移前的随机标签省略，不改变候选接受、拒绝或评分。

事故样本固定为：

- 当前画廊：`https://e-hentai.org/g/4112860/eebe6c1886/`
- 错误候选：`https://e-hentai.org/g/1478533/8a0b6013fd/`
- 关键差异：`Boy Meets Girl!` 对 `Boy Meets Girls 2`，且标题署名前缀与作品编号冲突。

正常样本固定为：

- 同一作品的罗马音／日文标题和中译版本，例如 `Odoroke Odoroke Daifuntou da yo Kogasa-chan!`。
- 同一作品的不同语言、Digital／展会标记差异，以及一方缺少日文副标题的合法版本。

C1 不改变候选搜索、接受、拒绝或评分；它只在普通标签并集完成后，对每个实际写入目标单独规划 `other:uncensored`。

已批准并在 `0.2.4.1` 实施的边界：

- GN/GJ 仅扫描 `[]`、`()`、`【】` 元数据段，按英中日韩正向、否定和邻接否定词分类；正负并存为冲突，否定式为未知。

- 本任务复用已取得的完整画廊快照，POST 后重新读取标签并验证；不会扫描、撤销或踩掉历史上已经误加的标签。

C1 与下方 M2–M6 相互独立。它已经完成审批，不表示任何待批准的匹配规则获得授权。

## 建议的批准顺序

1. 先确认 M2 的编号词法与例外。
2. 再确认 M3/M4 的高风险触发条件和所需证据数。
3. 最后决定是否需要 M5 的候选集合一致性，以及 M6 的页数弱证据能否计入门槛。

M1 只是锁定现行安全语义，不产生新行为。任何批准后的实现都必须先扩充事故拒绝与正常翻译接受黄金样本，再修改生产规则。
