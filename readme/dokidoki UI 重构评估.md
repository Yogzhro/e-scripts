# dokidoki Monster Lab UI 重构评估

> 当前状态：审核后的核心布局已同步到本地 `dokidoki 0.2.1.0` 与 `HV Monster Manager 0.3.5.0`；本轮未推送、未发布、未创建标签，图片仍读取 `dokidoki-v0.2.0.0`。

## 结论

Monster Lab 适合改造成高密度实验室工作台，但生产实现不应复制 Hentaiverse 或 HV Utils 的数据和操作节点。名册应继续使用真实 `.msl` 行，详情页继续保留原生输入与提交节点，dokidoki 只负责布局、主题、导航和可选的 HV Monster Manager 挂载区。

离线原型保留两个独立滚动区用于密度比较；生产版采用兼容性更高的“连续分半双列＋单滚动区”，不移动 `.msl` 的直接父节点。怪物属性与技能合并为一个档案外壳，工具栏按自身容器宽度折行，管理器把精确求解、手动编辑、水晶属性和混沌升级统一成一个不分页的 24 项矩阵。

## 已知真实页面基线

此前对主站 Monster Lab 做过只读检查：页面包含 200 个怪物行；安装 HV Utils 后每行有 9 个直接属性子节点，另有真实工具栏、排序栏和底部原生操作区。主内容和滚动区存在固定宽高，详情属性与技能分处两个页面。

生产版明确不把 `.msl` 移进两个滚动容器：全部怪物仍为 `#slot_pane` 直接子节点，每行内部 9 个属性节点不变，双列只由 CSS Grid 的显式行列位置实现。真实页面仍需在发布前复核 Console、Network、HV Utils 排序及属性／技能表单；本地实现和测试不等于真实账号写操作验收。

## 离线预览信息架构

顶部只保留约 48px 的轻量导航和预览控制：怪物名册、PL 计划器、怪物重命名，以及语言、宽度、图片失败模拟和小型“离线预览”徽标。怪物档案不占顶级导航，只能从名册进入。

已删除以下冗余区域：

- “紧凑怪物实验室工作台／名册与状态总览／完整立绘仅……”说明区。
- “dokidoki · Monster Lab／离线界面预览，不连接 Hentaiverse”品牌栏。
- 分离的属性页与技能页入口。

## 双滚动名册

- 桌面继续采用 `220px + minmax(0, 1fr)`：左栏放槽位统计、搜索、种族筛选和管理器入口，右侧放工具按钮、排序、双名册与底部操作栏。
- 名册宽度达到 `1180px` 时显示两个独立垂直滚动区；1536 和 1280 预览为双区，1024、900、640、375 自动合并为单区。
- 当前排序和筛选结果按中点连续分半，奇数结果由左区多一项；初始编号排序为左区 `#1–#100`、右区 `#101–#200`。
- 两区使用同一批 200 个 `.msl` 节点，不复制怪物数据。每行仍有 9 个直接属性子节点。
- 每张档案卡高 86px，缩略图显示为 `48×72`，槽位只在画像角标显示为 `#1`，虚构名称末尾不再重复 `001／002`。
- 所有数值都带同步中英文标签：`PL`、`胜／杀`、`新礼／总礼`、`情绪／饥饿`。其中“新礼”对应 HV Utils 的 `gains`，“总礼”对应 `gifts`，不再出现含义不明的裸数字。
- 标签被放在原有 9 个属性节点内部，不增加 `.msl` 直接子节点；375px 下改为六行卡片，以保留礼物与状态信息而不产生横向滚动。
- 搜索、种族筛选和排序触发统一重排并把两个滚动位置归零；进入档案再返回不会重排，因此保留筛选、选择和左右滚动位置。
- 单击或 Space 只选择；双击或 Enter 打开 `#monster/<slot>`；上下键在当前区移动，左右键在双区间跳到最接近的索引。
- 使用 `ResizeObserver` 与预览宽度设置共同决定双区／单区，避免只依赖浏览器媒体查询。

## 合并怪物档案与技能

- 路由统一为 `#monster/<slot>`，从被打开的虚构怪物实时更新编号、名称、种族、PL、状态、战绩、礼物和对应占位立绘。
- 档案最大宽度约 1240px，宽屏采用 `280px 立绘 + 弹性档案区`，不再保留独立第三栏。
- “主要属性”“伤害与减免”“其他属性”合并为横跨档案区的“战斗属性”卡。宽屏左栏依次放 6 项主属性与 FIRE、COLD、ELEC、WIND、HOLY、DARK 六项元素减伤，右栏放攻击伤害／类型、物理与魔法减伤、攻击速度、闪避率和抵抗率；900px 及以下依次堆叠。
- “照料与身份”与“危险操作”合并为“照料与管理”。喂养、安抚、重命名位于普通区域，释放怪物位于同卡片底部的红色描边危险分区，不再使用整张红色危险卡。
- 混沌升级完整显示 HV Utils 的 12 项名称、等级和双语效果说明：Scavenging、Fortitude、Brutality、Accuracy、Precision、Overpower、Interception、Dissipation、Evasion、Defense、Warding、Swiftness。1536／1280 为 6 列，1024／900 为 4 列，640／375 为 2 列。
- 技能配置保留在同一档案页并使用两列技能卡。所有照料、重命名、技能保存和释放按钮永久禁用。
- 901–1100px 立绘缩为约 `240×360`；900px 及以下改为立绘置顶的单栏，技能卡同步改为单列。

## 自适应实验室工具栏

- 断点以 `#dokidoki-toolbar` 的实际容器宽度为准，不使用页面宽度代替组件宽度。
- 容器不小于 1020px 时，9 个真实工具按钮固定为一行；640–1019px 使用 5 列形成 `5 + 4` 两行；小于 640px 时收进“实验室工具”折叠区。
- 折叠区按 `utility / data / monster / manager` 分组，每组使用两列按钮，并持续显示工具数量。按钮和折叠控制的最小高度均为 44px。
- 宽、中屏使用不换行的紧凑显示名；完整中英文名称保留在 `title` 与 `aria-label`，不会因为视觉缩写丢失可访问名称。
- 工具栏模式由一个 `ResizeObserver` 和单一同步函数维护；进入窄屏前后保留折叠区的运行期展开状态。

## 一体化 PL 升级工作区

PL 计划器保持单页，不增加标签页、步骤条或分页。升级矩阵本身就是草案，页面顺序固定为：计划设置、始终展开的升级编辑器、可折叠的资源需求、可折叠日志。

### 数据与编辑

- 选择器列出虚构怪物并支持多选；所有选中怪物同时进入编辑器，不截断、不分页。
- 每只怪物包含固定身份列：编号、名称、当前 PL、投影 PL 与单怪重置。
- 可编辑目标共 24 项：STR、DEX、AGI、END、INT、WIS；FIRE、COLD、ELEC、WIND、HOLY、DARK；以及完整 12 项混沌升级。
- 每格同时显示当前等级与目标等级。主属性上限 25，元素减伤上限 50，12 项混沌升级上限 20；空值、非整数、低于当前值或越界值原样保留并标错，阻止计算、确认和执行，不自动钳制。
- 提供单项输入、整组 `+1`、主属性／元素拉平、单怪重置和全部重置。所有按钮都有可见文本或完整键盘标签，不依赖左右键差异。
- 桌面矩阵在自身容器内横向和纵向滚动，双层分组表头及身份列保持粘滞，不扩大页面宽度。
- 900px 及以下切换为连续怪物卡；每卡按主要属性、元素减伤、混沌升级分组。当前、已修改或出错的卡自动展开，用户手动展开的其他卡在重绘后继续保持。

### 求解、草案状态与资源

- 初始草案等于当前等级，因此无需先计算即可手动规划。
- “计算精确方案”只求解主要属性和元素减伤，直接写回矩阵；混沌升级保持当前等级。成功后草案标记为“精确方案”。
- 任一手动调整会重新分类草案并立即重算投影 PL、水晶、混沌令牌与缺口。
- 修改水晶属性的怪物必须精确达到目标 PL；只修改混沌的怪物可忽略 PL 差异；同一批可混合精确 PL 和仅混沌怪物。投影偏离目标或输入无效时草案直接无效，而不是允许带警告执行。
- 自定义草案再次计算时先显示覆盖确认；确认后才重置全部手动目标并写入新方案，取消则保留当前编辑。
- 资源区汇总 12 种水晶和混沌令牌，默认只显示需求大于 0 的项目，并可展开全部 13 项。发生缺口时自动展开并逐项标出需求、库存和缺口；没有缺口时不擅自改变用户的折叠状态。
- 日志只在错误时自动展开；普通计算、编辑和重置不会强制打开日志。
- 离线预览仅启用本地计算、编辑、重置、选择和折叠。购买、提交订单和执行升级按钮永久 disabled，且不会初始化真实市场缓存或执行循环。

### 档案入口

- 怪物档案的“战斗属性”和“混沌升级”标题各有“在 PL 计划器中升级”入口。
- `#planner/<slot>` 会打开单页计划器、选择对应虚构怪物并聚焦矩阵行或窄屏卡片。
- 档案中的主要属性、元素减伤和混沌等级仍为只读，不复制第二套输入、资源计算或提交控件。

## HV Monster Manager 可选兼容

- PL 计划器与怪物重命名预览保持 `280px + minmax(0, 1fr)` 两栏：左侧表达真实文件管理器式怪物选择器，右侧保持管理器栏目顺序；PL 编辑器可在较窄桌面宽度下收窄选择栏。
- 选择、安全摘要、水晶数据、升级方案、重命名输入和日志仍由管理器唯一维护；dokidoki 只提供布局、颜色变量和 `#dokidoki-addon-host`。
- 900px 及以下改为选择器在上、操作区在下。未安装管理器时，生产版不得留下空入口或空列。
- 继续保留 `#dokidoki-shell`、`#dokidoki-toolbar`、`#dokidoki-list-view`、`#dokidoki-addon-host`、`data-dokidoki-view` 和 `dokidoki:ready` 契约。

## 设计系统

- 页面 `#E3E0D1`；主纸面 `#F7F2E4`；次级纸面 `#EEE5D1`；高亮纸面 `#FFF9EC`。
- 主文字和深色按钮 `#3F302B`；次级文字 `#74665D`；边框 `#B9A78A`。
- 主强调琥珀 `#9B6A24`；次强调黄铜 `#B27A28`；成功 `#2F6A3B`；危险 `#8E2636`。
- 酒红 `#5C0D11` 仅用于“离线预览”徽标中的 6px 圆点，不用于大背景、普通按钮、卡片、边框或选中行。
- 标题使用本地 Georgia，正文与控件使用本地 Verdana；不加载网络字体。
- 控件高度至少 44px，提供明显焦点状态、`listbox/option` 语义和 `prefers-reduced-motion` 降级。

## 安全与兼容边界

- 预览包含 200 只虚构怪物，不读取账号、Cookie、登录态、文件输入或持久存储。
- 页面没有 Fetch、XHR、表单提交、Service Worker 或 PWA；所有可能写入账号的按钮都为 disabled。
- 正式版不复制排序、表单或管理器节点，不虚拟化怪物行；管理器仍自行维护并安全提交原有站内操作。
- 生产名册已经采用 `#slot_pane` 内 CSS Grid 连续分半，不改变 `.msl` 直接父节点；离线双滚动区只是保留的视觉比较原型。
- dokidoki 与 HV Monster Manager 继续互不依赖；任一脚本缺失或挂载失败时都应回退到原有可操作布局。

## 审核与下一步

请直接通过 `file://` 打开仓库根目录的 `dokidoki-preview.html`，重点审核：

1. 1536／1280 下左右滚动是否比单根长滚动更易浏览。
2. 86px 卡片与 48×72 占位图的密度是否合适。
3. 双击进入档案、Enter／Space 和方向键逻辑是否自然。
4. 名册的 `PL／胜／杀／新礼／总礼／情绪／饥饿` 标签是否足够清楚，同时没有让 86px 卡片显得拥挤。
5. 合并后的“战斗属性”左右分组是否易读，“照料与管理”的危险分区是否足够醒目但不过度抢眼。
6. 12 项混沌升级在 6／4／2 列布局下是否兼顾密度与完整名称的可读性。
7. 9 个工具在一行、`5 + 4` 两行和分组折叠三种模式下是否清楚且不拥挤。
8. 桌面升级矩阵的粘滞身份列、24 项横向浏览和窄屏连续怪物卡是否易于比较与编辑。
9. 精确 PL／仅混沌／混合批次／无效输入／资源缺口反馈是否足够明确，但没有制造重复方案列表。
10. 1024 以下单区、900 以下单栏档案及管理器两栏降级是否合适。
11. 深棕、纸面、琥珀与黄铜是否贴近原站，酒红是否已经足够克制。

当前本地实现已经同步生产脚本和离线预览关键规则。下一步仅剩真实页面的只读布局／网络核验和用户人工审查；在确认前不推送、不发布、不创建标签，也不发送升级、购买、重命名、照料或技能保存请求。
